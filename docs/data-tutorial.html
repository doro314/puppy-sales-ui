Managing your litters

Everything visitors see about the puppies comes from one file. This guide shows you how to change it with confidence — and there's a practice editor below where nothing you type can reach the real site.

1How it works

The puppies, their litter, the dates and health details all live in src/data/litters.json. Photos live in folders next to it. You change the file; the site follows.

1EditChange a word in litters.json — a status, a weight, a date.
2SaveVS Code underlines anything that isn't allowed, right as you type.
3PublishCommit and push. The site checks the file before anything changes.
4LiveA minute or two later, visitors see the update.

You can't break the live site. If the file has a mistake, the update simply stops and the site stays exactly as it was. The message tells you where the mistake is and what to type instead.

2Reading the file

The file is a list of facts in a strict format called JSON. It looks busy at first, but it's only four kinds of thing.

{ ← a group of facts starts
  "slug": "maple",          ← a fact: "label": value
  "name": "Maple",
  "status": "available",    ← words go in "quotes"
  "color": ["white", "black"], ← [ ] is a list
  "weights": [
    { "date": "2027-02-07", "oz": 24.5 }
  ]                           ← numbers: no quotes
} ← the group ends

Three rules that prevent most mistakes

  1. Words in "double quotes". Numbers and true / false go without quotes.
  2. A comma between items — never after the last one. Adding something to a list? Put a comma after the item before it.
  3. Everything that opens, closes. Every { has its }, every [ its ].

Values are lowercase: "available", not "Available". Dates are YEAR-MONTH-DAY with two-digit months and days: "2027-02-07".

5Doing it for real, in VS Code

The real file works like the practice editor, with extra help: VS Code knows every allowed value and fills in whole puppies for you.

Open the file

  1. Open the puppy-sales-ui folder in VS Code.
  2. In the file list, open src → data → litters.json.
  3. Make your change and save with ⌘ S.

Let VS Code help

  1. Allowed values: click inside the quotes of a value and press ⌃ Space (Control and Space). A list of every allowed value appears, each explained.
  2. A whole new puppy: click inside a litter's "puppies": [ … ] list and press ⌃ Space, then choose New puppy. Press Tab to jump between the blanks. New litter works the same way inside "litters".
  3. Mistakes: anything not allowed gets a wavy underline. Point at it to read why.
"slug": "maple", "name": "Maple",
"status": "|"
"available"
"reserved"
"adopted"

Want to see a change before it goes live? In VS Code's terminal run npm run dev and open the address it shows. A mistake appears there too, as a red box with the same message.

  • Order: photos show in file-name order. To lead with a different photo without renaming anything, add "cover": "IMG_1876.jpeg" to the puppy (or the litter) — spelled exactly like the file, capitals included.
  • Formats: JPEG, PNG, WebP and AVIF work. iPhone HEIC photos don't show in browsers — export them as JPEG, or set Settings → Camera → Formats → Most Compatible so the phone saves JPEGs.
  • No photos yet? That's fine. The puppy shows "Photos coming soon" until you add some.
  • Size doesn't matter: drop in full-size photos. The site makes small copies for phones by itself.

7Publishing your changes

"Publishing" means saving a snapshot of your change (a commit) and sending it to GitHub (a push). The site rebuilds itself from there.

  1. In VS Code, click the Source Control icon in the left bar (it shows a number when files have changed).
  2. Type a short note about what you changed — "Maple reserved", "Week 5 weights".
  3. Click Commit, then Sync Changes (or Push).
  4. Wait a minute or two and reload the site.

Didn't change? On GitHub, the latest commit shows a red ✗ when the check stopped the update. Click it to read the message — it's the same one you'd see here — fix the file, and publish again.

8Allowed values

Read straight from litters.schema.json — the same list VS Code suggests and the check enforces. Add a new word there (say, a new color) and all three know it.

9When the check says no

Every message names the place (litter › puppy › field) and what to do. The ones you're most likely to meet:

The message saysWhat to do
"Available" isn't an allowed value … Did you mean "available"?Values are lowercase. Use the suggestion.
"2027-2-7" doesn't fit. Write dates as YYYY-MM-DDUse two-digit months and days: 2027-02-07.
Should be a plain number, like 31.5 — not "31.5 oz"Weights are numbers of ounces, with no quotes and no "oz".
This isn't valid JSON … missing or extra commaLook at the line it names (and the one before): a comma missing between items, an extra one after the last item, or a missing quote.
"status" is missing — every puppy needs itEvery puppy needs a slug, name, sex and status.
The slug "bella" is already used …Each puppy needs its own slug, across every litter. Try bella-2.
"IMG_1876.jpg" isn't in src/images/… The file there is "IMG_1876.JPEG"Copy the file name exactly, capitals included.
No litter has "listed": trueKeep at least one litter listed — the sold-out one is fine until the next arrives.

Some messages are only warnings — a puppy with no photos yet, a HEIC file. They never stop an update.
